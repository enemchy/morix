# Руководство по использованию ролей

В инструменте Morix имеется возможность задавать роль через аргумент командной строки `--role`. Роль определяет, какой 
системный промт будет использоваться в процессе взаимодействия с языковой моделью, а также влияет на манеру и стиль ответов. В данном руководстве описаны назначения основных ролей, порядок их редактирования и создание новой роли.

## Основные роли

### 1. developer

- **Назначение**: Роль "developer" предназначена для разработки, исправления ошибок и улучшения функциональности проекта. Системный промт для этой роли ориентирован на технические задачи и подробное описание технических деталей.
- **Использование**: По умолчанию используется роль `developer`, если не задана иная роль через аргумент `--role`.

### 2. analyst

- **Назначение**: Роль "analyst" ориентирована на анализ требований, сбор 
документации и постановку задач для разработки. Промт содержит подробные инструкции по сбору и валидации требований, что помогает формировать более структурированные задания для разработчиков.
- **Использование**: Для запуска в аналитическом режиме задайте аргумент `--role analyst`.

### 3. reviewer

- **Назначение**: Эта роль используется для проведения
обзора (ревью) кода и анализа изменений. Системный промт для роли `reviewer` содержит рекомендации по оптимизации кода, улучшению производительности и безопасности, а также проверки соответствия стандартам.
- **Использование**: Для запуска в режиме ревью используйте `--role reviewer`.

## Редактирование промптов для ролей

Промты для ролей хранятся в виде markdown файлов в директории `morix/promts/`. Каждый файл имеет формат `role.<имя_роли>.md`. Например:

- `morix/promts/role.developer.md`
- `morix/promts/role.analyst.md`
- `morix/promts/role.reviewer.md`

### Как редактировать промт для существующей роли

1. Перейдите в папку `morix/promts/`.
2. Откройте файл с именем соответствующей роли, например, `role.developer.md`.
3. Измените содержимое файла, внося необходимые поправки или добавляя дополнительные указания.
4. Сохраните изменения.

### Как создать свою собственную роль

1. Создайте новый файл в директории `morix/promts/` с именем `role.<имя_роли>.md`, где `<имя_роли>` — это название вашей новой роли (например, `role.manager.md`).
2. Определите назначение новой роли, опишите требования к стилю общения и функциональным особенностям.
3. Пример содержания для новой роли:

    ```markdown

    # Ваша роль: Manager

    - Вы отвечаете за управление процессами и контроль выполнения задач.
    - Обеспечиваете баланс между техническими требованиями и бизнес-целями.
    - Ваш промт должен содержать рекомендации по приоритетизации задач, обеспечению коммуникации между отделами, а также по контролю качества.
    ```

4. После создания файла и внесения текста, при запуске Morix можно использовать новый аргумент:

   ```shell
   morix --role manager
   ```

   Это позволит системе автоматически подгрузить ваш промт для используемой роли.

## Заключение

Использование ролей позволяет гибко настраивать взаимодействие с языковой моделью, адаптируя ответы под конкретные задачи. Редактирование или создание новой роли выполняется посредством изменения/добавления markdown файлов в директории `morix/promts/`.

Следуя данным инструкциям, вы сможете эффективно настраивать систему под свои потребности, улучшая качество взаимодействия и результаты работы инструмента Morix.
